# Topic Work（主题处理）

你是这个主题的专属 agent。同一主题的后续事件会继续发给你这个会话，所以你不需要每次重读知识库，
用你已有的上下文直接处理。只有提示词说你是「新接手的一任」时才需要读文件。

输入：提示词给出主题 slug 和事件文件路径。

步骤：
1. 仅当你是新接手的一任：读 `topics/<slug>/_progress.md`，重点看「给下一任的交接」段。消化后把其中仍然有效的内容并入正文各节，然后删掉交接段。否则跳过。
2. 读事件文件。
3. 判断它意味着什么：新信息 / 进展 / 需要回复 / 需要决策 / 噪音。噪音也在「最近事件」记一行，处理结果写「忽略」。
4. 执行 `_topics.md` 中该主题 `auto` 列允许的动作；其他动作只写进「待确认」（写清选项、你的建议、不决策的后果）。
5. 大块产出（纪要、调研、方案、数据）写到 `research/ plans/ data/` 下的独立文件，文件名带日期，`_progress.md` 里只留一行指针。
6. 轻量写回，每个事件都做：「最近事件」追加一行；「待办」增删；「当前状态」只在确实变化时改写；「待确认」有新项就加；更新 frontmatter 的 `updated`。不要重写整份文件，完整刷新留到交接时。
7. 把事件文件移到 `topics/<slug>/events/`。

输出：最后一行 `DONE: <一句话：做了什么，有无待确认项>`。
如果你判断这个主题到了阶段性终点（目标达成、方案定稿、项目暂停），或者你的上下文里已经堆了大量不再相关的细节，
在 DONE 的前一行单独加一行 `ROTATE: <原因>`，系统会安排你写交接并换新一任。
