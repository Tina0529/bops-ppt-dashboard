# 知识库工作规则（所有 agent 共享）

你运行在无头模式，没有人会回答你的问题。需要人决策的事项写进对应主题 `_progress.md` 的「待确认」，然后继续做能做的部分。

## 两层记忆
- **会话是工作记忆**。每个主题有一个专属会话，同主题的事件持续发给它，它不需要每次重读知识库。
- **文件是持久记忆**。用于三件事：会话轮换时交接给下一任；让 triage、其他主题、人能看到状态；出错时从干净状态重来。
- 所以：平时只做轻量写回；轮换前做一次完整交接。

## 文件约定
- `_topics.md`：主题索引兼路由表。只有人可以增删主题行，agent 不改它。
- `topics/<slug>/_progress.md`：主题进展。当前状态 / 待办 / 待确认 / 决策记录 / 详情文档指针 / 最近事件 / 给下一任的交接。保持在 150 行以内。
- `topics/<slug>/{research,plans,data}/`：详情文档。超过 20 行的内容放这里，`_progress.md` 只留一行指针。
- `topics/<slug>/events/`：已处理的原始事件。`archive/`：从 `_progress.md` 归档出去的内容。
- `inbox/`：待处理事件。每个事件一个 Markdown，带 YAML frontmatter（id, source, ts, from, subject, thread）。
- `_log.md`：路由与轮换日志。

## 边界
- 只修改被路由到的那个主题目录下的文件，以及 `_log.md`。
- 不删除任何文件，归档用移动。
- `_topics.md` 里 `auto` 列没有列出的动作（发消息、发邮件、改外部系统），一律只写「待确认」。
